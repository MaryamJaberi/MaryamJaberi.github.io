# قواعد مشترک برای همهٔ ابزارها (Antigravity، Google AI Studio، Claude)

این فایل را هر ابزار هوش مصنوعی که روی «اطلس زمان» (Earth Through Time) و «ویکی تبار» کار می‌کند باید اول بخواند.

## یک مخزن اصلی

- مخزن اصلی و منبع حقیقت: `MaryamJaberi/earth-through-time-new`، شاخهٔ `main`.
- Google AI Studio مخزن جداگانهٔ خودش را دارد: `MaryamJaberi/Atlas-studio`. گردش‌کار `.github/workflows/aistudio-sync.yml` هر ۳۰ دقیقه آن را با این مخزن همگام می‌کند:
  تغییر AI Studio → PR با شاخهٔ `from-aistudio`؛ و `main` این مخزن → `main` مخزن AI Studio.
  تا وقتی متغیر `AISTUDIO_REPO` در تنظیمات این مخزن ساخته نشده، این پل خاموش است.
- تاریخچهٔ مخزن AI Studio هرگز با این مخزن ادغام نمی‌شود؛ فقط محتوا جابه‌جا می‌شود. روی مخزن AI Studio مستقیم کار نکن.
- Antigravity و Claude مستقیم روی همین مخزن کار می‌کنند.
- نسخهٔ منتشرشده در سایت مریم (`MaryamJaberi.github.io/earth-through-time/`) هر شش ساعت خودکار از `main` همین مخزن کپی می‌شود.
- این سایت HTML و JavaScript ساده است، بدون مرحلهٔ build. ساختار را به React یا ابزار دیگر تبدیل نکن، مگر مریم بخواهد.

## کدام ابزار برای چه کاری

| ابزار | بهترین کاربرد |
|---|---|
| Google AI Studio | نمونهٔ اولیهٔ ابزارهای تعاملی تازه، قابلیت‌های Gemini، Google Maps برای لایه‌های نقشه |
| Antigravity | کار روی کامپیوتر خودت: اسکریپت‌های داده (مثل `build-paleo.py`)، دادهٔ حجیم، اجرای محلی، تغییرهای بزرگ چندفایلی |
| Claude | محتوا و منابع، داده و مصورسازی، ویکی تبار، بازبینی و Pull Request، رفع باگ |

## روش کار

1. پیش از شروع، آخرین `main` را بگیر (`git pull`).
2. برای هر کار یک شاخهٔ تازه بساز (`feature/...` یا `fix/...`)، نه کار مستقیم روی `main`.
3. پیش از push: `index.html` و `tabar/index.html` را در مرورگر باز کن؛ کنسول نباید خطای تازه داشته باشد. روی عرض گوشی هم نگاه کن.
4. تغییر را با Pull Request به `main` بفرست. merge را مریم انجام می‌دهد.
5. فایلی را بدون پرسیدن پاک نکن.
6. هر داده یا عدد تازه منبع دارد؛ آینده همیشه «پیش‌بینی/فرض» برچسب می‌خورد، نه پیش‌گویی.

## امنیت

- هیچ کلید، توکن یا رمزی وارد مخزن نمی‌شود (`.env` در `.gitignore` است). جزئیات در [SECURITY.md](SECURITY.md).
